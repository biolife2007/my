# Моніторинг URL Магнум

Python 3.6+ на Linux, сторонні пакети не потрібні. Файли в public_html/cli/magnum/.

`19.xlsx`: перший аркуш, A — URL, B — SKU, C — назва. Заголовки необов'язкові.
Кожен запуск читає поточний файл. Дозволено лише домен hmel-master.com.

Скопіюйте config.example.json у config.json і заповніть bot_token та chat_id.
Бот має бути запущений користувачем кнопкою Start або доданий до потрібної групи.
Файл config.json має бути доступний лише власнику (chmod 600). .htaccess забороняє HTTP-доступ
до всієї папки; для nginx потрібна еквівалентна заборона у конфігурації сервера.

Перевірки:

    python3 monitor.py --inspect
    python3 monitor.py --dry-run
    python3 monitor.py

Перший звичайний запуск повідомляє про всі підтверджені 404. Наступні — лише про нові.
404 підтверджується двома GET-запитами. 403, 410, 429, 5xx, помилки мережі та одиночні 404
не вважаються підтвердженим зникненням. Після відновлення 2xx наступне зникнення знову викликає повідомлення.
Кожне повідомлення містить SKU, назву та URL. Коли нових зникнень немає, Telegram мовчить.
Невдалі доставки залишаються непідтвердженими і повторюються наступного запуску.
У разі неоднозначного тайм-ауту Telegram можливе повторне повідомлення.

Стан: state.json. Остання перевірка: latest-results.json/csv. Dry-run не змінює стан
і не надсилає повідомлень. monitor.lock не дозволяє одночасні запуски.

У cron використовуйте абсолютні шляхи до Python і скрипта та спрямовуйте вивід у monitor.log.
Узгоджений розклад: щовівторка о 08:00 за Europe/Kyiv.
Перед додаванням розкладу перевірте часовий пояс cron хостингу: TZ усередині процесу
не змінює часовий пояс розкладу cron. Потрібний день і час узгоджуються з користувачем.
